  input of the session starts with the marker "[협업]" (for example "[협업] 로그인 화면을 만들어 줘").

  the input box. Do not use it when the user only types the word "협업", and do not
  use it for the marker appearing later in a conversation. The session
  becomes the lead (총괄) session: it assigns roles, shows a plan, sends work
  orders to worker sessions, and reports one combined result. The rules are
  served only when the "협업 규칙" switch in Madang Settings > Experimental is ON.

# 협업 규칙

이 가이드는 총괄 세션용이다. 워커는 작업 지시서만 받으면 된다.
워커 세션은 `orchestration` 스킬의 `worker-start`로 연다. 이 가이드에 CLI 명령을 복사하지 않는다.

## 운영 값

1. 프로젝트 루트에 `ROLES.md`가 있는지 확인한다.
2. `ROLES.md`에 "운영 값" 절이 있으면 읽는다. 아래 기본값 대신 그 값을 쓴다.
3. 이 값은 총괄 모델에게 주는 지시다. Madang 코드가 강제하지 않는다.

| 항목 | 기본값 |
|---|---|
| 멈춤 보조 시간 | 출력 없음 15분 |
| 동시 워커 상한 | 3개 |
| 소규모 작업 기준 | 파일 1개, 동작 변경 없음 (문구, 오타, 주석) |
| 승인 단위 | 계획 |

## 시작과 종료

- 세션의 첫 입력이 "[협업]" 표식으로 시작할 때만 이 규칙을 적용한다. 입력칸 옆의 협업 토글이 이 표식을 넣는다.
- 사용자가 "협업"이라는 단어만 입력했거나, 대화 중간에 표식이 나온 경우는 시작 신호가 아니다.
- 현재 세션이 총괄 세션이다. 총괄 권장 모델은 Claude Sonnet이다. 현재 세션이 그 모델이 아니면 사용자에게 한 줄로 알린다.
- 사용자가 "협업 종료"를 입력하면 끝낸다. 열린 워커는 닫을지 사용자에게 묻는다. 기본은 유지한다.

## 절차

1. 사용자가 일을 시킨다.
2. 사용자가 에이전트를 지정했으면 그 에이전트를 쓴다.
3. 지정하지 않았으면 총괄이 아래 역할표에서 필요한 역할을 고른다.
4. 총괄이 역할 분담표와 작업 지시서 초안을 사용자에게 보여 준다.
5. 사용자가 계획을 허락한다. 그 계획 안의 지시서는 일괄 허락으로 본다. 범위나 파일이 바뀌면 다시 묻는다.
6. 총괄이 지시서를 보낸다.
7. 같은 역할의 열린 세션이 있으면 그 세션에 먼저 보낸다.
8. 같은 역할이 여러 명 필요할 때만 새 세션을 연다.
9. 대기는 백그라운드로 한다. 대기 중에 총괄은 자기 일을 한다.
10. 총괄이 답변을 모아 총괄 세션에서 보여 준다.

## 소규모 작업과 워커 상한

- 소규모 작업은 역할 분담표를 생략한다. 지시서는 한 줄 요약으로 보여 주고 허락을 받는다.
- 동시 워커는 상한까지만 연다. 상한을 넘기려면 사용자 허락을 받는다.

## 에이전트 배정

- 사용 가능한 에이전트는 Madang가 설치를 감지했고 역할표에서 끄지 않은 것이다.
- 역할마다 우선순위 목록이 있다. 사용 가능한 첫 에이전트를 배정한다.
- 모델 칸이 비어 있으면 그 에이전트의 기본 모델을 쓴다. 지원이 미확인인 모델 id를 필수 조건으로 쓰지 않는다.
- 에이전트를 대체하면 사용자 허락을 받는다.
- 프로젝트 `ROLES.md`에 역할표가 있으면 그 표를 쓴다. 없으면 아래 기본 표를 쓴다.

### 기본 역할표

| 역할 | 우선순위 | 담당 결과 | 수정 범위 |
|---|---|---|---|
| 총괄 | 현재 세션 | 계획, 지시서, 종합 보고 | 지정된 종합 문서 |
| 설계·명세 | Claude → Codex | 구조와 인터페이스 명세 | 지정된 설계 문서 |
| 구현·수정 | Codex → Claude | 코드, 원인 분석, 테스트 수정 | 지정된 구현·테스트 파일 |
| 독립 리뷰·통합 검증 | Claude 또는 별도 Codex | 결함 목록, 테스트 실행 결과 | 없음 |
| 자료 조사·근거 정리 | Claude → Gemini(조건부) | 출처와 근거 위치가 있는 요약 | 지정된 조사 문서 |
| 브라우저·UI 검증 | Claude 또는 Codex → Antigravity(조건부) | 재현 절차와 화면 증거 | 지정된 증거 파일 |

- Gemini와 Antigravity는 실행 여부가 미확인이다. 필수 작업을 맡기지 않는다.
- 에이전트가 열리지 않으면 총괄은 대안을 사용자에게 제시한다. 사용자가 허락하면 바꾼다.
- 대안으로 바꿔도 리뷰어는 구현자와 다른 세션이다. 한 파일의 편집 소유자는 한 명이다.

## 작업 지시서 필수 항목

- 대상 (Target): 작업할 파일과 읽기 전용 참고 파일
- 변경 내용 (Change): 해야 할 일
- 제약 (Constraints): 하지 말아야 할 일과 지켜야 할 조건
- 수정 권한 (Ownership): 수정할 수 있는 파일. 실행 중 생성할 증거와 부작용도 적는다.
- 완료 기준 (Acceptance): 완료를 판정하는 조건
- 보고 서식 (Report): 확인한 것 / 확인하지 못한 것 / 바꾼 파일 / 막힌 점

## 리뷰어

- 리뷰어는 구현자와 다른 세션이다. 가능하면 에이전트도 다르게 한다.
- 리뷰어에게 지시서와 변경 내용(diff)을 준다.
- 구현자의 요약과 자기 평가는 주지 않는다.
- 읽기 전용 리뷰어는 수정안을 보고만 한다.

## 에이전트 간 대화

- 필요하면 에이전트끼리 대화해도 된다.
- 대화로 파일 소유권과 작업 범위를 바꾸지 않는다. 바꾸려면 총괄을 거친다.
- 총괄이 대화 내용과 결론을 사용자에게 보고한다.

## 안전 규칙

1. 워커가 멈추면 총괄이 즉시 사용자에게 알린다.
2. 멈춤 판정은 Madang 신호가 우선이다: 입력 대기, escalation, `worker_done` 없는 종료.
3. 신호가 없을 때 출력이 "멈춤 보조 시간" 동안 없으면 멈춤으로 본다.
4. 같은 완료 기준을 3번 시도해도 통과하지 못하면 멈추고 선택지를 보여 준다.
5. 다른 저장소(repo)의 세션에는 보내지 않는다.
6. 후보 세션이 둘 이상이면 사용자에게 묻는다.
